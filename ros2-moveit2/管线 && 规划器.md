本文介绍 Moveit2 中的管线（pipeline）。

管线（pipeline）是「流程容器 + 配置」，规划器插件（planner plugin）是「真正干活的算法实现」。管线负责加载插件、串起前后处理，插件负责算出轨迹。


PlanningPipeline  （管线，名字如 "ompl"）
│
├── ① request_adapters      请求预处理：修起点、检查碰撞、补工作空间边界…
│
├── ② PlannerManager        规划器插件（如 ompl_interface/OMPLPlanner）
│       │                   ← 真正做搜索 / 优化的 C++ 插件（.so）
│       └── PlanningContext
│             └── planner_id: RRTConnect / RRT / PRM …   ← 插件内部的算法
│
└── ③ response_adapters     结果后处理：时间参数化、平滑、校验…
职责对比
管线 pipeline	规划器插件 planner plugin
本质	配置 + 流程编排	实现 planning_interface::PlannerManager 的动态库（.so）
来源	config/<name>_planning.yaml	YAML 里的 planning_plugin / planning_plugins 字段
负责	读参数、加载插件、跑适配器、调用 solve()	提供算法，实际算出轨迹
数量	可有多条（ompl、chomp…）	一条管线可加载一个或多个插件
选择方式	MotionPlanRequest.pipeline_id	MotionPlanRequest.planner_id
名字的对应关系
管线名和插件名通常相近但不相同：

管线名	插件（planning_plugin(s)）	插件提供的算法
ompl	ompl_interface/OMPLPlanner	RRTConnect、RRT、PRM…
chomp	chomp_interface/CHOMPPlanner	CHOMP
stomp	stomp_moveit/StompPlanner	STOMP
pilz_industrial_motion_planner	pilz_industrial_motion_planner/CommandPlanner	PTP、LIN、CIRC

管线（pipeline）        ompl / chomp / stomp / pilz        ← 一条完整流水线
   └─ 规划插件/算法库      OMPL / CHOMP / STOMP / Pilz
        └─ 具体算法        RRTConnect / RRT* / PRM ...     ← OMPL 内部再选
所以严格说：OMPL 和 CHOMP 是「规划器插件」，不是单一算法；OMPL 里面还装着二十多种算法。

1. OMPL 是什么
Open Motion Planning Library，开源 C++ 运动规划库，MoveIt 的默认和最常用规划器。

类型：基于采样的规划（sampling-based）
原理：在关节空间里随机采样，做碰撞检测，把可行点连成树或图，再找一条从起点到终点的路径
特点：
✅ 不需要初始轨迹
✅ 通用、probabilistically complete（采得足够久，理论上一定能找到解）
❌ 结果是随机的，每次路径可能不同
❌ 轨迹通常不平滑（后期靠时间参数化/平滑处理）
❌ 维度越高越慢
它包含的算法可以分几类：

类型	代表算法	说明
单查询（树）	RRTConnect、RRT、RRT*、TRRT、BiTRRT、EST、BiEST、KPIECE、BKPIECE、LBKPIECE、SBL、STRIDE	每次请求重新搜索，适合一次性规划
多查询（图）	PRM、PRM*、LazyPRM、LazyPRM*、SPARS、SPARStwo	先建路网，适合同一场景反复规划
渐近最优	RRT*、PRM*、FMT*、BFMT*、LBTRRT	时间越久路径越优
后处理	AnytimePathShortening	对已有路径做缩短/优化
你仓库 ompl_planning.yaml 里只启用了其中 3 个：


planner_configs:
  RRTConnect: { type: geometric::RRTConnect, range: 0.1, goal_bias: 0.05 }
  RRT:        { type: geometric::RRT, ... }
  PRM:        { type: geometric::PRM, ... }
代码里 req.planner_id = "RRTConnect"，所以实际用的是 RRTConnect：从起点和终点各长一棵树、互相连接，速度较快，是 MoveIt 最常用的默认算法。

2. CHOMP 是什么
Covariant Hamiltonian Optimization for Motion Planning，基于梯度优化的轨迹规划器。

原理：先给一条初始轨迹（通常是关节空间直线），然后迭代优化一个代价函数：
平滑项（smoothness）
障碍物代价（obstacle cost）
用梯度下降让轨迹既平滑又避障
特点：
✅ 生成的轨迹很平滑
✅ 给定初值是确定性的，结果可复现
✅ 可以带约束优化
❌ 必须有初始轨迹
❌ 容易陷入局部极小（复杂障碍、窄通道可能失败）
❌ 需要代价函数可微
典型参数就是你之前看到的 ridge_factor: 0.01（平滑正则项）。

3. 还有哪些？
MoveIt 2 核心仓库里常见的还有两个：

STOMP
Stochastic Trajectory Optimization for Motion Planning，随机轨迹优化。

不需要梯度，适合不可微的代价函数
可以从一条「不可行」的初始轨迹（甚至纯噪声）开始优化
结果平滑，但随机、非确定性
常见参数：num_timesteps、num_iterations、num_rollouts
Pilz Industrial Motion Planner
工业运动规划器，确定性地生成标准工业轨迹：

指令	含义
PTP	Point-to-Point，关节空间点到点
LIN	笛卡尔直线运动
CIRC	笛卡尔圆弧运动
适合「先直线移动到 A，再直线插进孔里」这类工业流程；不适合自由空间避障寻路。

其他（视安装而定）
TrajOpt / Tesseract：基于优化的外部插件（不在 MoveIt 核心）
SBPL：基于搜索的栅格/格点规划器（ROS 1 时代更常见）
自定义插件：实现 planning_interface::PlannerManager 就能接入
4. 对比总结
管线	类型	需要初值	轨迹平滑度	确定性	典型用途
OMPL	采样	否	一般	随机	通用避障、抓取
CHOMP	梯度优化	是	好	是（给定初值）	平滑轨迹、初值较好
STOMP	随机优化	否（可用噪声初值）	好	随机	平滑 + 复杂代价函数
Pilz	解析/工业	否	好	是	PTP / LIN / CIRC


# 附录
## OMPL 管线
```yam
# ompl_planning.yaml
# 标准 MoveIt OMPL 规划配置 (moveit 官方 setup assistant 生成格式):
# 顶层 planning_plugin/request_adapters/start_state_max_bounds_error/jiggle_fraction 必须保留,
# 否则 MoveIt 无法识别 OMPL 为当前 pipeline 的插件 (planning_plugin 会取默认值而误用 CHOMP,
# 而 CHOMP 库缺失导致 ompl pipeline 初始化失败)。
# 组名对应 dual_ur5e_moveit_config/config/dual_ur5e.srdf: left_arm / right_arm / dual_arms.
#
# 重要: planner_configs 的段名必须是规划请求 planner_id 的名字 (不能带 "Config" 后缀),
# 否则 OMPL planning_context_manager 报
#   "Cannot find planning configuration for group '<group>' using planner '<id>'. Will use defaults instead."
# 并退回默认配置 (无 range/goal_bias) 时在 12 维空间 segfault。
# planner_node 的 req.planner_id = "RRTConnect", 故段名就叫 RRTConnect。

planning_plugin: ompl_interface/OMPLPlanner
start_state_max_bounds_error: 0.1
jiggle_fraction: 0.05
request_adapters: >-
    default_planner_request_adapters/AddTimeOptimalParameterization
    default_planner_request_adapters/ResolveConstraintFrames
    default_planner_request_adapters/FixWorkspaceBounds
    default_planner_request_adapters/FixStartStateBounds
    default_planner_request_adapters/FixStartStateCollision
    default_planner_request_adapters/FixStartStatePathConstraints

# 基础 planner 参数模板 (段名 = planner_id 名)
planner_configs:
  RRTConnect:
    type: geometric::RRTConnect
    range: 0.1
    goal_bias: 0.05
  RRT:
    type: geometric::RRT
    range: 0.1
    goal_bias: 0.05
  RRTstar:
    type: geometric::RRTstar
    range: 0.1
    goal_bias: 0.05
  PRM:
    type: geometric::PRM
    max_nearest_neighbors: 10
  KPIECE:
    type: geometric::KPIECE
    range: 0.1

# 左臂 规划组
left_arm:
  planner_configs:
    - RRTConnect
    - RRT
    - PRM

# 右臂 规划组
right_arm:
  planner_configs:
    - RRTConnect
    - RRT
    - PRM

# 双臂联合组 (12 维)
dual_arms:
  planner_configs:
    - RRTConnect
    - RRT
    - PRM
```

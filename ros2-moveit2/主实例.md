
```c++
moveit_cpp_ = std::make_shared<moveit_cpp::MoveItCpp>(shared_from_this());
```
这一行内部做了五件事：

加载机器人模型：用 RobotModelLoader 读节点参数 robot_description（URDF）和 robot_description_semantic（SRDF），建出 robot_model_。所以后面 getRobotModel() 能直接拿到。
建 PlanningSceneMonitor：绑定这个节点和机器人模型。
启动三个 monitor（关键）：
startStateMonitor() → 创建 CurrentStateMonitor，订阅 /joint_states
startWorldGeometryMonitor() → 订阅 /collision_object、/planning_scene_world 等
startSceneMonitor() → 订阅 /planning_scene
另外 startPublishingPlanningScene() → 往 /monitored_planning_scene 发完整场景
加载 planning pipeline：读参数 planning_pipelines.pipeline_names 和各 pipeline 的参数，建出 PlanningPipeline。
准备轨迹执行：读 moveit_controllers 配置，让后面的 moveit_cpp_->execute("dual_arms", traj) 能把轨迹发给 action server。

为什么放在 init() 而不是构造函数里？ 因为 shared_from_this() 要求对象已经被 shared_ptr 持有。在 PlannerNode 构造函数执行期间，main 里的 std::make_shared<PlannerNode>() 还没返回，shared_from_this() 会抛 std::bad_weak_ptr。所以他们拆成 构造 → node->init() 两步（planner_node.cpp:549）。

第 2 行：providePlanningSceneService()
对外提供 get_planning_scene 服务（moveit_msgs/srv/GetPlanningScene），返回当前完整场景：机器人关节状态 + 世界碰撞对象 + attached objects、以及可选的子集分量。

用途是给外部客户端拉取真实现场状态，而不是自己拼 diff：

RViz 的 MotionPlanning 插件在某些操作（刷新场景、交互式目标）会调用它；
你自己写的脚本、别的节点也可以 ros2 service call /get_planning_scene ... 来看 planner 眼里的世界。
如果不调这行，/monitored_planning_scene 话题照样有（构造函数里发的），但 service 不存在，客户端会报 service not available。

一个注意点：如果这个节点和 move_group 同时运行，两者都会 advertise 同一个 /get_planning_scene，会冲突。你的 planner.launch.py 里没有 move_group，所以没问题。

第 3 行：startSceneMonitor()（planner_node.cpp:64）
订阅 /planning_scene（默认话题），接收外部发来的场景增量更新（PlanningScene diff）：RViz 里加碰撞体、别的节点发布障碍物、attached object 变化等。收到后合并进内部 PlanningScene，再通过 /monitored_planning_scene 把完整场景广播出去。

方向容易记混：


外部 ──/planning_scene (diff)──► PlanningSceneMonitor ──/monitored_planning_scene (完整)──► RViz
你的 moveit.rviz:22 配的就是 Planning Scene Topic: monitored_planning_scene。

但这一行基本是多余的：按 MoveIt 2 里 MoveItCpp 的实现，构造函数内部已经把 scene/world/state 三个 monitor 全 start 了——否则你上一轮看到的 getCurrentState() 不可能实时更新（代码里从没自己调 startStateMonitor()）。所以第 3 行是重复调用，无害（会重建一次 /planning_scene 订阅），但可以删掉。

不是拷贝，是 MoveItCpp 构造函数里创建的那个 PlanningSceneMonitor 的共享指针。生命周期跟着 moveit_cpp_，你拿到的是"句柄"。
之所以有 NonConst 版本：providePlanningSceneService()、startSceneMonitor() 这些方法都是非 const 的，必须通过非 const 指针调。MoveItCpp 通常还提供 getPlanningSceneMonitor()（const 版本，返回 ConstPtr）。
这个对象是 MoveIt 场景系统的中枢：它自己持有 PlanningScene（世界模型）、CurrentStateMonitor（关节状态）、octomap/碰撞对象订阅、get_planning_scene 服务、/monitored_planning_scene 发布器。
